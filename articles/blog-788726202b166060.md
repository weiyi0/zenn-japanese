私のブログ [weiyii.cn](https://weiyii.cn) では、ページ調整、多言語化、検索エンジンへの送信、WeChat の下書きまで GPT を使っています。

最初は「サイトをどう最適化する？」「Baidu にまだ登録されないのはなぜ？」と、大まかな質問をしていました。使ううちに、気になる箇所を直接伝えるほうが進むと分かりました。文字が詰まっているなら文字を、スマホで表が読めないなら表を直す。具体的な問題ほど結果が見えます。

今は私が問題を伝え、GPT がプロジェクトを読み、ファイルを変更して確認し、最後に公開ページを見る流れです。

## まず自分が読みにくいと感じるところから

ブログで大切なのは読みやすさ。トップページを見渡せるか、本文が小さすぎないか、見出しが重くないか、スマホで表が読めるか。普通のことですが、読者は最初にそこに触れます。

こんなふうに頼みます。

> 記事ページのフォントとサイズを調整して、スマホも確認してください。表は本文領域の幅を使い、広すぎるものは横スクロールを残してください。

対応するページとスタイルを探してから変更してもらいます。**「UI を最適化して」だけで好みの見た目になるとは限りません。** 違和感を伝え、変更後はパソコンとスマホで開き、必要なら再調整します。

PageSpeed も同様です。リンクを渡して報告と実装を照合してもらう。原因探しには役立ちますが、実際に速く開くか、読みやすさを損なわないかを確認します。スコアは参考、使うのは人です。

## 多言語化は翻訳だけでは終わらなかった

英語、スペイン語、ロシア語、日本語、アラビア語を追加しました。本文以外にも、タイトル、概要、カテゴリ、タグ、メニュー、共有時の文言があります。アラビア語には右から左への表示も必要でした。

言語ごとに独立した URL があり、英語は /en/articles/…/、日本語は /ja/articles/…/ です。開くとその言語の本文が表示されます。

hreflang、x-default、canonical も GPT に確認させました。名前は難しそうですが、目的は単純です。**同じ記事の言語別ページと、その正しい URL を検索エンジンに伝えること。**

直近の確認では、370 の外国語ページと対応する中国語ページが合格しました。一つずつ開くより一括確認が楽です。ただし翻訳は抜き取りで見ます。技術用語一つで文の意味が変わることがあります。

## 送ったのに、なぜ検索に出ない？と私も思った

サイトを検索で見つけてほしいので、Sitemap や Baidu の登録状況を聞き、全リンクの送信も依頼しました。

送信成功とインデックス登録成功は混同しやすいところです。今はどの段階が終わったかを分けて見ます。

| 検索サービス | 送信方法 |
| --- | --- |
| IndexNow | 公開ページの URL |
| Google | Search Console API で Sitemap を送信 |
| Baidu | 枠内でリンク送信 API を利用 |

この記事の前の公開時、IndexNow は全サイト 438 URL を受け付け、Google も Sitemap を受け付けました。Baidu は当日の上限に達し、残りは後日に持ち越しました。

438 URL の受付は、438 ページの登録を意味しません。クロールと登録は検索サービス側で確認します。**GPT は送信できますが、いつ何を登録するかは検索エンジンが決めます。**

一般的なブログ記事向けに、Google には IndexNow と同様の汎用的なページ単位の登録要求 API はありません。私は Sitemap API を使っています。

## 記事が増えると、毎回の手作業を減らしたくなる

執筆後には翻訳、ビルド、ページ確認、アップロード、キャッシュ更新、リンク送信。その後に WeChat の表紙、レイアウト、概要、原文リンクが続きます。

繰り返す作業を GPT にスクリプト化してもらいました。次も同じ流れを使い、失敗した場所はログで分かります。

WeChat の下書きも API でアップロードしています。対応するタイトル、著者、概要、表紙、原文リンクを設定し、読み戻して確認。再試行の前に既存の下書きを調べ、通信失敗による重複を防ぎます。

下書きまでを任せ、公開前には自分でスマホの表、段落、表紙を見直します。

## 使うほど「全部最適化して」と言わなくなった

問題、期待する動作、確認方法の三つを伝えます。

> スマホで記事の表が画面からはみ出しています。横スクロールを残して修正し、中国語と英語のページを確認してください。原因と検証結果を教えてください。

または、

> 公開ページを IndexNow に送り、応答を記録してください。失敗分は再試行待ちにし、送信成功を登録成功とは書かないでください。

きれいな文章より、必要な情報です。「完了」の後も公開サイトを見ます。ローカルのビルド成功は、キャッシュ更新や検索送信の成功を保証しません。

Baidu の上限不足や IndexNow の過去状態の検証失敗もありました。後者は既存の全サイト送信スクリプトで対応しました。ひと言で「全部成功」とするより、結果を分けて説明し、残りを終えるほうが役立ちます。

## 毎回最初からやり直さなくていい

スタイル探し、リンク確認、翻訳ファイル整理、下書き準備。小さな時間が積み重なります。今は具体的な問題を渡して結果を確認でき、保存した手順を次も使えます。

何を書くか、何を公開するか、読みやすいかは自分で判断します。まずはスマホの表一つ、記事の言語ページ一組、下書きのアップロードから。ひとつ動かして次を足す。私のブログも、そうやって少しずつ改善してきました。
