![家に Thread ボーダールーターが2台あれば、デバイスは必ず安定する？](https://ay3s.com/images/covers/thread-multiple-border-routers.webp)

リビングに Thread 対応スピーカーを1台置き、書斎にも Thread 機能を備えたデバイスを1台追加した。台数が倍になれば、ドア・窓センサーはオフラインになりにくくなり、どちらか1台の電源を抜いても使い続けられるのでしょうか？

その可能性はあります。ただし、まず確認すべきことがあります。**その2台のボーダールーターは、同じ Thread ネットワークを支えているのでしょうか？**

Thread では、1つのネットワークで複数のボーダールーターを使用できます。これにより、通信範囲を広げ、単一障害点を減らせる可能性があります。しかし、「家に Thread 対応デバイスが2台ある」ことと、「同じ Thread ネットワークに利用可能な出口が2つある」ことは別です。[1][2]

以前、[Matter と IPv6 の紹介](https://ay3s.com/ja/articles/matter-ipv6-local-network/)で、ボーダールーターの基本的な役割を説明しました。今回は、もう少し実際的な問題を見ていきます。デバイスを増やす前に、それが既存のネットワークに役立つかどうかを、どう判断すればよいのでしょうか。

この記事は公式資料に基づいてまとめたもので、確認日は 2026 年 11 月 9 日です。以下の家庭内の状況とテスト手順は設計上の例であり、実機テストの結果ではありません。

## 2台のデバイスでも、構成はまったく異なる場合がある

Thread ボーダールーターは、Thread ネットワークと Wi-Fi やイーサネットなどの別の IP ネットワークを接続し、両者の間でデータをやり取りできるようにするとともに、サービス検出にも関わります。[3]

2台のボーダールーターが同じ Thread ネットワークに設定されていれば、そのネットワークに複数の出口を提供できます。Thread Group は、複数のボーダールーターで同じメッシュネットワークを構成するための重要な条件として、Thread ネットワーク認証情報の共有を挙げています。[2]

一方、リビングの1台がネットワーク A を作り、書斎の1台がネットワーク B を作っている場合もあります。どちらも同じ家庭内 LAN に接続されていても、使用する Thread ネットワーク認証情報は異なります。

この場合、すでに A に参加しているドア・窓センサーは、B のボーダールーターのほうが近いというだけで、それを自分の予備の出口として自動的に使うことはできません。Home Assistant のドキュメントも、認証情報が異なる Thread ネットワークは分かれており、デバイスはその間をローミングできないと明記しています。[1]

2つのケースを並べると、次のようになります。

| 家庭内の実際の構成 | 期待できること | それだけでは判断できないこと |
| --- | --- | --- |
| 2台のボーダールーターが同じ Thread ネットワークに参加している | 同じネットワークの出口が増え、通信範囲と冗長性を改善する条件が整う | すべての部屋で電波状態がよいこと、切り替えに必ず遅延がないこと |
| 2台のボーダールーターがそれぞれネットワークを作っている | それぞれが所属ネットワークを支え、デバイスは家庭内 IP ネットワークを通じて通信できる場合もある | A のデバイスが自動的に B に参加できること、または2つのメッシュの無線通信範囲が統合されたこと |

ここで、別の誤解にも注意が必要です。**Thread ネットワークが2つあるからといって、両方のデバイスがまったく連携できないわけではありません。**

ルーティング、サービス検出、制御権限がそろっていれば、異なる Thread ネットワーク上のデバイスも、家庭内 IP ネットワークを経由してコントローラーと通信できます。Thread Group はこのケースを説明しています。ネットワークが分かれていても、上位システムから IP デバイスとして利用することは妨げられません。ただし、2つのネットワークの無線通信範囲や予備の出口を、1つのネットワークのものとして数えることはできません。[2]

## 2つのアプリで操作できても、ネットワークの出口が2つあるとは限らない

もう1つ混同しやすいのは、同じ Matter 対応ドア・窓センサーが Apple Home と Home Assistant の両方に表示される場合です。これは、そのデバイスが同時に2つの Thread ネットワークに接続しているということでしょうか？

そうは判断できません。

Matter のマルチプラットフォーム対応が扱うのは、制御の関係です。デバイスは異なる Matter Fabric に追加でき、複数のプラットフォームがそれぞれ制御権限を持てます。一方、Thread ネットワークは基盤となる通信を担います。[2][4]

したがって、デバイスが元の Thread ネットワークを使い続けながら、2つのプラットフォームからの制御を受けることは可能です。2つ目のプラットフォームを追加しても、利用可能な Thread ボーダールーターが自動的に1台増えるわけではなく、デバイスが Thread ネットワーク間をローミングできるようになるわけでもありません。

逆に、既存の Thread ネットワークにボーダールーターを追加しても、別のプラットフォームにデバイスの制御権限が与えられるわけではありません。

この2点は、別々に確認する必要があります。

- ネットワーク面：デバイスはどの経路を通って家庭内 LAN に到達できるか？
- 制御面：状態の読み取りやコマンドの送信に必要な権限を、どのプラットフォームが取得しているか？

2つ目のプラットフォームへのペアリングで困っているなら、[1台の Matter デバイスを2つのプラットフォームに接続する方法](https://ay3s.com/ja/articles/matter-multi-admin-sharing/)も参照してください。制御プラットフォームを増やすために、安定して動いている Thread ネットワークを先にすべて作り直す必要はありません。

## Home Assistant にネットワークが表示されても、認証情報を取得済みとは限らない

Home Assistant の Thread ページはボーダールーターを検出し、Thread ネットワークごとにまとめて表示します。家庭内に実際にいくつのネットワークがあるかを確認するのに役立ちます。[1]

ただし、デバイスを検出することと、ネットワークへの参加に必要な認証情報を取得することは別の段階です。

公式ドキュメントによると、ボーダールーターが mDNS/DNS-SD を通じて公開するローカル検出情報には、Thread ネットワーク認証情報は含まれません。そのため、一覧にネットワークが表示されても、Home Assistant が自分のボーダールーターをそこに参加させられるとは限りません。[1]

今回の確認時点で、Home Assistant はスマートフォンの Companion App を通じて認証情報をインポートし、新しい Home Assistant ボーダールーターを既存のネットワークに参加させる手順を提供しています。ただし、スマートフォンのプラットフォーム、認証情報にアクセスできるかどうか、新しいボーダールーターがすでに独自の Thread ネットワークを持っているかどうかなど、具体的な前提条件があります。[1]

特に、ドキュメントにある制限に注意してください。OpenThread ボーダールーターが該当する手順で優先ネットワークに参加するのは、まだ Thread ネットワークを持っていない場合に限られます。「優先ネットワーク」の切り替えを、既存のすべてのデバイスの自動移行と捉えてはいけません。また、ドキュメントは、スマートフォンを使ったプロビジョニングで使用する優先ネットワークには、スマートフォン側の状態も関係すると注意しています。[1]

実際に作業する際は、現在のバージョンの説明と照らし合わせて、次の点を確認してください。

1. 既存のデバイスがどの Thread ネットワークに属しているか。
2. 新しいボーダールーターをどのネットワークに参加させる予定か。
3. 設定に使うスマートフォンと管理プラットフォームが、必要な認証情報を利用できるか。
4. 完了後、管理画面でボーダールーターが想定したネットワークの下に表示されるか。

ネットワーク名は識別の助けになりますが、2つの名前が同じというだけで設定も一致していると判断しないでください。また、鍵を含む完全なネットワーク認証情報を、相談のためにフォーラムへ投稿したり、スクリーンショットに載せたりしないでください。

## 2つ目の出口ができても、残る単一障害点を確認する

2台のボーダールーターが確かに同じネットワークに属しているとします。それだけで「家にはもう障害対策ができている」と言えるでしょうか？

ほかの依存関係も確認する必要があります。

あるスマートスピーカーが、Thread ボーダールーターと家庭内のコントローラーを兼ねている場合があります。その電源を抜くと、ネットワークの出口と自動化の実行を担う機器を同時に失うかもしれません。2台目のボーダールーターがデータを転送し続けても、元の自動化が動き続けるとは限りません。[1][4]

同様に、2台とも停電する同じ電源タップにつながっていたり、両方とも故障した同じ Wi-Fi アクセスポイントに依存していたりすれば、その共通の障害には対処できません。

設置場所も実際の効果に影響します。2台ともリビングのテレビ台のそばに押し込んであるだけでは、壁を何枚も隔てた寝室のデバイスに、よりよい無線経路ができたとは言えません。

そのため、2台目を購入する前に、解決したい問題を明確にしてください。離れた部屋の通信範囲が足りないのか、ある出口の停止に備えたいのか、それともコントローラーの故障に備えたいのか。ボーダールーターの台数が答えるのは、その一部だけです。

## 記録を残しながらテストし、役に立っているか確認する

以下は検証方法の提案であり、プロトコルで定められた固定のテスト基準ではありません。

まず、一般的な照明、コンセント、またはテスト用センサーを選び、ドアロックや警報装置など安全に影響するものは避けます。通常時の操作結果、状態の報告、普段使う自動化を1つ記録してから、条件を1つずつ変えます。

| テスト | 操作条件 | 観察する点 |
| --- | --- | --- |
| 基準状態 | 2台のボーダールーターとコントローラーがすべて正常に動作 | コマンド、状態、自動化が正常か |
| 出口 A の停止 | B、コントローラー、ローカルネットワークは維持 | 通信が回復するか、回復にかかる時間、報告の欠落があるか |
| 出口 B の停止 | A を復旧させてから、B だけを停止 | 別の経路が実際に利用できるか |
| 通信範囲の端 | 実際の使用場所でテスト用デバイスを動作させる | 通信範囲が改善したか、断続的な接続断が残るか |

電池式センサーでは、実際に状態を一度変えて報告を確認できます。アプリに表示された古い状態だけを見ないでください。電源を抜く対象がコントローラーも兼ねている場合は、その点を結果に記録し、失敗をすべて Thread のせいにしないでください。

また、「電源を抜いた後、一度だけ照明を点けられた」ことをもって、家庭内から単一障害点がなくなった証拠にしてはいけません。回復時間、状態の変化、自動化の結果を記録して初めて、2台目が具体的にどのように役立ったかが分かります。この記事には実測に基づく根拠はないため、切り替えにかかる秒数を一律に保証することはしません。

## 2台目を買う前に、最初のネットワークを把握する

Thread では、複数のボーダールーターが同じネットワークを支えられます。これは有用な機能です。ただし、購入する台数、所属するネットワーク、制御権限、実際に利用できるかどうかは、それぞれ確認する必要があります。

既存のデバイスが安定して動いており、ある出口が停止しても別の経路を確保したいだけなら、同じネットワークに参加させられるか、共通の依存先がないかを先に確認し、出口を1つずつ停止させるテストを行うほうが、単に Thread のロゴが付いた機器を1台増やすより役立ちます。

最後に、販売元への質問も具体的にできます。**この製品は、公式にサポートされた手順で、既存の Thread ネットワークに参加できますか？ 元のボーダールーターが停止した後、既存のデバイスとコントローラーはどのように通信できますか？**
