![Home Assistantのバックアップが成功すれば、別のマシンでも必ず復元できる？](https://ay3s.com/images/covers/home-assistant-backup-restore.webp)

バックアップ一覧に緑色の成功表示がある。これで安心してマシンを替えられると思ったのに、旧ホストを実際に停止してから、バックアップファイルが旧ディスクに残ったままで、復号鍵も別に保存しておらず、外部データベースもバックアップしていなかったことに気づく。

この種の問題で重要なのは、**バックアップタスクの完了が証明するのは、そのタスクが担当する部分を完了したということだけ**だ。スマートホーム全体を復元できるかどうかは、ファイル、鍵、依存サービス、ハードウェアも確認する必要がある。

この記事はHome Assistantの公式バックアップ文書に基づき、2026年11月10日時点で確認した内容を扱う。主にHome Assistant OSについて説明し、Containerとの対象範囲の違いも明示する。復元チェックリストは提案であり、ユーザーの家庭用機器で移行や障害対応の演習を実施したものではない。

## まずバックアップの中身を確認し、次にファイルサイズを見る

Home Assistant OSのバックアップには、設定、履歴データ、メディア、共有ディレクトリ、選択したアプリとそのデータを含められる。実際に含まれる内容は、バックアップ時に選択した項目によって異なる。[1]

ファイルが正常に生成されても、すべての項目を選択したとは限らない。サイズが小さいのは、メディアや履歴を除外しただけかもしれないし、本当に必要なデータが漏れているのかもしれない。サイズが大きくても、完全なバックアップとは証明できない。

公式文書では、データベースの場所も区別している。標準のデータベースにある履歴は、選択に応じてバックアップに含められる。データベースをHome Assistant OSのアプリとして動かしている場合は、そのアプリを含める必要がある。別のシステムで動かしている場合、そのデータベースはこのバックアップに含まれず、別途対処が必要だ。[1]

Home Assistant Containerのバックアップ対象範囲もOSと同じではない。文書に挙げられている主な内容はHome Assistantの設定と、任意で含める履歴データだ。同じホスト上のほかのコンテナ、ボリューム、デプロイ用ファイルまでまとめられたとは考えられない。

移行前に、実際の依存関係を表にしておくとよい。

| 項目 | 確認すること |
| --- | --- |
| Home Assistantの設定 | 現在必要な設定とオートメーションが含まれているか |
| 履歴とエネルギーデータ | どのデータベースを使用し、該当するバックアップに含まれているか |
| MQTTやデータベースなどのサービス | OSのアプリで動いているか、別のコンテナや別のマシンで動いているか |
| メディアと共有ディレクトリ | 除外されていないか、外部ファイルは別に保存してあるか |
| USB無線アダプター | 元のアダプターを残しているか、デバイスのマッピングをどう復元するか |
| ネットワークと外部アカウント | 新しいホストからアクセスできるか、再認証が必要か |

この表は棚卸しのための道具だ。各項目がバックアップ済みかどうかは、インストール方式、設定、実際のバックアップ内容に基づいて判断する必要がある。

## ファイルも復号鍵も、旧ホストだけに置かない

Home Assistantの文書によると、バックアップは標準で暗号化される。バックアップの設定時には、復元に必要な鍵を含む「emergency kit」（緊急時用資料）のダウンロードを促される。[1]

暗号化されたバックアップを保管する場合、復元には対応する鍵が必要だ。鍵を旧マシンのダウンロードフォルダーにしか置いていなければ、旧ディスクの故障とともに失う可能性がある。鍵だけを保存しても、バックアップファイルを取得できなければ同様に復元できない。

旧ホスト以外の場所に読み出せるコピーを保管し、対応する鍵も適切に保管することを勧める。鍵を変更したことがあるなら、古いバックアップがどの鍵を使っているかも確認する必要がある。現在ダウンロードできる緊急時用資料ですべての過去のファイルを復号できるとは限らない。

ダウンロードまたは転送したファイルが暗号化されているかどうかも確認したい。拡張子だけで判断してはいけない。コピーが復号済みのアーカイブなら、機密性の高い設定ファイルとして扱い、安易に公開クラウドストレージへアップロードしないこと。

公式文書は、コピーを別のシステムに保存し、理想的には遠隔地にもコピーを残すよう勧めている。[1] 家庭での利用なら、まず「旧ホストがまったく起動しなくても、ファイルと鍵を見つけられる」状態にするほうが、同じディスクに毎日ファイルを一つずつ増やすより意味がある。

## 圧縮ファイルを置ける容量があっても、復元を完了できるとは限らない

バックアップファイルは圧縮アーカイブだ。そのサイズから、新しい機器に必要な容量を直接推定することはできない。

Home Assistantの移行文書では、旧システムで実際に使用しているディスク容量を確認し、移行先に余裕を持たせるよう求めている。復元の条件には、移行先システムが正常な状態にあることや、ネットワーク接続も含まれる。[1]

したがって、数百MBのバックアップを見て、空き容量が数百MBあるストレージなら何でも足りると考えるべきではない。インストールされるプログラム、復元後のデータベース、アプリ、メディアには、さらに多くの容量が必要になる可能性がある。

また、「ローカル制御はインターネットに依存せずに行える」ことは、「システム全体の再構築にもインターネットが不要」という意味ではない。公式の復元手順ではHome Assistant Coreとアプリが再インストールされ、Home Assistant OSの復元に関する条件にはインターネット接続が含まれる。[1]

移行の準備では、移行先のハードウェア、インストール方式、ストレージ、復元に必要なネットワークをまとめて確認する。復元中に画面へ一時的にアクセスできなくなっても、すぐに電源を抜くべきではない。公式の説明に従って進行状況を確認し、通常の再構築処理を中断しないようにする。

## ダッシュボードが戻っても、デバイスが再接続されたとは限らない

復元が完了すると、元のダッシュボードやオートメーションの設定が表示されるかもしれない。しかし、それらが依存する実際のデバイスも動作している必要がある。

たとえば、旧システムで使っていたUSB無線アダプターを新しいマシンに接続していない、または仮想マシンにそのデバイスを再マッピングしていない場合がある。画面にデバイス名が残っていても、失われた無線インターフェースの代わりにはならない。

Home Assistantの公式移行手順では、移行時に元のコントローラーまたは無線アダプターを接続するよう注意している。新しい内蔵Zigbee無線機に変更する場合は、設定の復元だけで無線ネットワークの移行が完了したと考えず、Zigbeeの移行手順に従う必要がある。[1]

ネットワークストレージも、実際に接続できるか確認したい。共有パスの設定を復元しても、電源の切れたNASが自動的に利用可能になるわけではない。バッテリー駆動のデバイスが一時的に利用できない場合は、そのデバイスに合った方法で起動させ、状態の報告を観察できる。すぐにシステムから削除しないこと。

別途デプロイしたサービスについては、対応するデータと接続設定が復元されているか、なおさら確認が必要だ。この記事は、どのようなMatter、Thread、Zigbeeハードウェアでも、Home Assistantのバックアップ一つだけで支障なく交換できるとは約束しない。

## 「復元成功」を観察できる結果に分ける

バックアップシステムが示す作成成功、失敗、最後に成功した日時などの状態は、バックアップ処理の異常を見つけるのに適している。ただし、それらの状態は復元演習の報告書ではない。[2]

自分のシステムに合わせて、次のような受け入れチェックリストを設けることを勧める。

1. 旧ホストが使えなくても、別の場所からバックアップを取得できる。
2. そのバックアップに対応する復号鍵と、バックアップ時に使用していたログイン認証情報を取得できる。
3. 適切な移行先環境で復元を完了し、ログインできる。
4. 重要なオートメーション、必要な履歴データ、アプリが存在するか確認する。
5. 実際の状態報告を一つ、通常のデバイス操作を一つ、リスクの低いオートメーションを一つ確認する。
6. 通知と外部の依存サービスを確認し、実際の復元所要時間を記録する。

演習は許容できるメンテナンス時間帯に、予備環境または明確な切り替え手順を用意して行う。復元したコピーと稼働中のインスタンスが同じデバイスを同時に制御したり、通知を重複して送信したりしないようにする。隔離環境で設定だけを確認した演習なら、「実際のデバイス操作は未検証」と正確に記録すべきだ。

復元処理では、選択した部分が上書きされる。検証前に現在のシステムの独立したバックアップと、元に戻すための条件を確保すること。古いバックアップが使えると証明するために、唯一使える現状を先に上書きしてはいけない。

## バックアップが本当に役立つのは、復元が必要になったとき

普段はバックアップが予定どおり完了しているか、離れた場所にあるコピーが利用できるかを確認できる。大きな変更や移行の前には、さらに復元対象範囲、鍵、外部の依存関係を確かめる必要がある。

書き留めておくべきなのは「自動バックアップを有効にした」ことよりも、**最後に復元できると確認したのはどのバックアップか、何が含まれ、どの部分はまだ検証していないか**ということだ。

そうすれば、次にマシンを替える際、緑色のアイコンではなく記録に基づいて判断できる。
