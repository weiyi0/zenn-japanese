いまClaude Codeでどのモデルを選ぶか聞かれたら、まずSonnet 5.5を勧めます。

ページを追加する、APIをつなぐ、テストを書く。要件がはっきりしていて結果を確認しやすい仕事なら、最初から一番高いモデルを使う必要はありません。原因が分からないバグや、複数のモジュールにまたがる変更が出てきたらOpus 5.5へ。Fable 5.1は、本当に難しく、腰を据えて調べる仕事に取っておきたいところです。

Haiku 5.5にも出番があります。記事へのタグ付け、項目の抽出、短い要約。件数が多くルールが明確な仕事なら、まず試す価値があります。一件ずつ最上位モデルに任せると、必要以上に料金がかかります。

今回話したいのは、実際の仕事からモデルを選ぶことです。Token単価が安くても、仕事が安く終わるとは限りません。横で五回も修正に付き合うなら、自分の時間も費用に入ります。

## まず、いま使っているバージョンを確認する

2026年10月12日時点で、公式資料の主な現行ラインアップは **Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1** です。

Claude Codeを最新版にすることと、最新モデルを使うことは別です。Claude Codeはツールで、その先のモデルはログイン方法、プロバイダー、設定で変わります。

二人とも「Sonnetを使っている」と言っていても、違う版かもしれません。現在の資料では、Anthropic APIの`sonnet`は5.5ですが、BedrockとGoogle Cloud Agent Platformでは4.5を指す場合があります。Microsoft Foundryの`opus`もOpus 4.6の場合があります。感想を比べる前に、完全なモデルIDを確認しましょう。直接APIなら次のように選べます。

```text
/model claude-sonnet-5-5
/model claude-opus-5-5
/model claude-haiku-5-5
/model claude-fable-5-1
```

エイリアスは更新されるので、再現したい場合は完全なIDが便利です。他社の環境は専用ID、デプロイ、アカウントの利用権限も確認してください。Claude Codeの現在の要件はOpus 5.5がv2.1.280以上、Sonnet 5.5がv2.1.284以上、Haiku 5.5はv2.1.293以上を推奨、Fable 5.1がv2.1.257以上。切り替えてエラーになったら、サービス障害を疑う前にここを見ます。

## SonnetとOpusをどう分けるか

管理画面に検索フィルターを追加する仕事を考えてみます。APIはあり、項目も決まっている。画面につなぎ、空の結果を処理し、テストを追加する。こういう仕事はSonnetから始めます。何をすればいいか明確で、確認も早いからです。

一方、「注文がたまに二重課金される。ローカルでは再現できない」だと話が変わります。コールバックが重複したのか、タイムアウトで再試行したのか、DBはコミットしたのに応答が返らなかったのか。まとめて調べ、修正後も正常な注文と再試行が正しく動くことを確かめる必要があります。

ここならOpusに予算を使いたい。複雑な推論や長いコーディング作業を想定したモデルです。パッチを書くより、どこを直すべきか突き止めるほうが大変な仕事があります。

Fableはさらに大きな仕事向けです。古いシステムを移行するのに、依存関係も移行計画もまだ調べる必要がある、といったケース。公式はFable 5.1を高度な推論と長期的なAgent作業に位置付けています。Opusのeffortを上げても評価を満たせないなら、Fableを比較対象にします。

ただし、高いモデルでも足りない証拠は作れません。ログ、再現条件、業務ルールがなければ、どのモデルも推測するしかない。何度も「もっと考えて」と頼む前に、その情報を補うほうが先です。

| モデル | 最初に試したい仕事 | 公式の相対レイテンシー |
| --- | --- | --- |
| Haiku 5.5 | 分類、抽出、ルーティング、短い要約、小変更 | 最速 |
| Sonnet 5.5 | 日常の開発、通常の修正、テスト | 速い |
| Opus 5.5 | 難しい原因調査、複雑なリファクタリング、設計判断 | 中程度 |
| Fable 5.1 | 難しい調査、長い自律作業 | 遅め |

速度は公式の相対比較で、私が四モデルを同条件で測った結果ではありません。見るべきは仕事が終わるまでの時間。出力が速くても修正を繰り返せば待つことになります。ビルドや外部APIが遅いなら、モデルだけ速くしても効果は小さいでしょう。

## Haikuの料金で見落としたくないこと

以下はAnthropic直接APIの標準料金、100万Tokenあたり米ドルです。キャッシュ、Batchなどの追加条件は含めていません。

| モデル | 入力 | 出力 |
| --- | ---: | ---: |
| Haiku 5.5：入力10万Token以下 | $0.10 | $0.50 |
| Haiku 5.5：入力10万Token超 | $0.50 | $2.50 |
| Sonnet 5.5 | $2 | $10 |
| Opus 5.5 | $4 | $20 |
| Fable 5.1 | $10 | $50 |

短い入力のHaikuは安い。でも長いコンテキストを持ち続けると単価が上がります。10万の判定は**一回のリクエストの全入力で、キャッシュの読み書きも含みます**。超えたリクエスト全体が高い料金になり、超過分だけではありません。過去のリクエストを再計算することもありません。

短文の一括処理と、大量のファイルを抱えたAgentでは、料金を別々に考えましょう。現在の四モデルは1Mコンテキスト、公式の最大出力は128K Tokenです。容量は便利ですが、依存パッケージ、ビルド生成物、同じログで埋める必要はありません。関連するコードと証拠を渡し、不要なものは先に絞ります。

計算例として、一回に入力5万Token、出力5千Token、キャッシュなしとします。

| モデル | この仮定での料金 |
| --- | ---: |
| Haiku 5.5 | $0.0075 |
| Sonnet 5.5 | $0.15 |
| Opus 5.5 | $0.30 |
| Fable 5.1 | $0.75 |

これは単純計算で、同じ仕事の実測ではありません。実際には出力、推論、ツール呼び出し、再試行が変わります。この仮定ならSonnet三回が$0.45、Opus一回が$0.30。やり直しで単価の差は消えますが、Opusが一回で終わることをこの表が保証するわけではありません。

Claude Codeはファイルを読み、ツールを実行し、結果を受け取り、また修正します。最初のメッセージだけでなく、完成までの全体を数えてください。

## 旧版よりどれだけ安くなったか

標準Token単価だけを比べると、次の通りです。

| 更新 | 旧入力／出力 | 新入力／出力 | 単価の変化 |
| --- | --- | --- | --- |
| Opus 5 → 5.5 | $5 / $25 | $4 / $20 | 20%低下 |
| Sonnet 4.6 → 5.5 | $3 / $15 | $2 / $10 | 約33.3%低下 |
| Sonnet 5 → 5.5 | $2 / $10 | $2 / $10 | 同じ |
| Haiku 4.5 → 5.5、短い入力 | $1 / $5 | $0.10 / $0.50 | 90%低下 |
| Haiku 4.5 → 5.5、長い入力 | $1 / $5 | $0.50 / $2.50 | 50%低下 |

tokenizerも変わっています。公式によるとClaude 4.7以降は、同じ文章が旧版より約30%多いTokenになることがあり、実際の増加は内容次第です。4.6以前からの移行では、単価が三分の一安くなっても請求が三分の一減るとは限りません。実際のリクエストを数え、最終使用量を比べます。

## 最初からeffortを最大にしない

Claude CodeではOpus 5.5、Sonnet 5.5、Haiku 5.5の現在の既定値はmedium、Fable 5.1はhighです。これはClaude Codeの設定で、APIモデルページの既定値と異なる場合があります。

```text
/effort medium
/effort high
```

日常はmediumから。情報がそろっているのに同じ箇所を何度も直すならhighを試します。文言変更までmaxにすると待ち時間や費用が増えかねません。欠けたログが手に入るわけでもないからです。

これらのモデルはlow、medium、high、xhigh、maxに対応しますが、組織設定で制限されることがあります。`opusplan`は計画時にOpus、実行時にSonnet。計画を決めるのが難しく、実装は比較的明確な仕事なら候補になります。

## 節約するなら、まず費用の行き先を見る

朝に決済を直し、午後にトップページ、夜に分析機能を追加する。一つの会話を続けると古いログや議論が入力に残ることがあります。段階が終わったら必要な背景と決定をまとめて、次へ進むほうが管理しやすいです。

キャッシュヒットは現在、100万TokenあたりOpus 5.5が$0.20、Sonnet 5.5が$0.10、Fable 5.1が$0.25。これは読み取りの料金で、書き込みは別です。通常入力、書き込み、読み取りを分けて計算します。

急がないAPIの一括処理ならBatchが標準入力・出力料金の50%。非同期処理なので、Claude Codeの対話も自動で半額になるわけではありません。

Opus 5.5のFast modeは入力$8、出力$40／100万Tokenで、通常の二倍。直接APIの研究プレビューです。モデル待ちなら意味があるかもしれませんが、テスト待ちなら追加料金で速くはなりません。

ProやMaxの含まれる使用量、追加usage credits、API請求は分けましょう。`/usage`のAPI料金見積もりが、そのまま追加請求とは限りません。Fableはプランや席の種類によって追加クレジットを使うので、選択画面の表示を確認してください。

## 個人開発者に一式そろえるなら

ブログや管理画面、普通の機能追加は **Sonnet 5.5 + medium** から。コードを読み、必要なテストを実行します。難しい障害や複数モジュールの変更は **Opus 5.5** へ。何時間も失敗を繰り返す前に切り替えたいところです。

短文処理は **Haiku 5.5** を試し、サンプルの間違いを確認してから量を増やす。**Fable 5.1** はさらに難しく長い仕事に。Opusより何を多く解決できるかで判断し、動ける時間だけを見ないようにします。

普段の仕事を二十～三十件選んで、費用、時間、結果、人による修正時間を記録してみてください。ランキングより、自分の予算に役立つはずです。払っているのはプロジェクトを終わらせるため。立派な答えでも全部書き直すなら、割に合いません。
