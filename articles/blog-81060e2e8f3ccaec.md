![家にルーターを2台設置したら、なぜリモートアクセスがかえって難しくなったのか？](https://ay3s.com/images/covers/double-nat-home-network.webp)

家に Mesh Wi-Fi を追加し、メインノードを光回線終端装置（ONU）の後ろにつないだとします。スマートフォンはインターネットにつながり、速度測定の結果も良好です。そこで NAS も新しいネットワークにつなぎ、外出先からいつでも写真を見られるようにしようとします。

ところが、家の中ではすべて正常に開けるのに、外出すると接続できません。

NAS に固定アドレスを設定し、ポート転送を設定し、ドメインまで購入しました。ルーターの設定画面ではどの項目も正しく見えるのに、リモートアクセスは失敗したままです。

この種の問題では、ポートを変え、再起動し、ソフトウェアを変え、また再起動する、という循環に陥りがちです。本当に足りないのは、数行で描けるネットワーク経路図であることが少なくありません。

**ある機器からインターネットへ接続できることは、インターネット側からその機器を見つけられることを意味しません。2台のルーターがどちらも正常に動いていても、設定が必要なのは片方だけとは限りません。**

この記事では、前の[戸建て住宅の Wi-Fi 構成](https://ay3s.com/ja/articles/villa-wifi-roaming/)と[回線が混雑したときの待ち時間](https://ay3s.com/ja/articles/bufferbloat-sqm/)に続き、電波の届き方や速度に目立った問題がなくてもリモートアクセスが失敗する理由と、ONU のブリッジ化、Mesh の AP モード、IPv6、メッシュ VPN などの接続ツールが、それぞれ経路のどの部分の問題を解決するのかを考えます。

先に選択の原則を示します。**目的が無線のカバー範囲を広げることだけなら、追加機器を AP モードで動かすことを優先して検討します。自分で購入したルーターで家全体を一元管理したいなら、ONU のインターネット接続をブリッジ化できるか検討します。どちらを選んでも、通信事業者側のアドレスと外部からの着信条件は別途確認が必要です。**

この記事は、標準規格と公式文書に基づいてまとめた構成分析と調査手順であり、特定の機種や回線で行った現場実測ではありません。本文中のアドレスとポートは説明用の例です。

## 一、箱の数ではなく、どの機器がルーティングしているかを見る

同じ「ONU の後ろにルーターを1台つなぐ」構成でも、意味はまったく異なる場合があります。

ONU はアクセス回線を下流へ引き渡すだけで、下流のルーターがインターネット接続を確立することもできます。一方、ONU 自身がルーティング、アドレス割り当て、NAT を担うこともあります。機器に印字された名称だけでは、現在の役割を判断できません。

さらに下流では、Mesh のメインノードがルーターモードで独立した内部ネットワークを作る場合もあれば、AP モードで既存のネットワークに無線端末を接続する場合もあります。

次の経路を想定してください。

```text
インターネット
  ↓
ONU：ルーターモード、LAN は 192.168.1.1/24
  ↓
Mesh メインノード：WAN は 192.168.1.2
                   LAN は 192.168.50.1/24、ルーター/NAT モード
  ↓
NAS：192.168.50.10
```

ONU と Mesh のメインノードがどちらもこの IPv4 経路で NAT を行っていれば、NAS からインターネットへ送るデータは2回のアドレス変換を経ます。これが家庭でよくある二重 NAT です。[1]

ただし、「ルーターが2台ある」ことが必ず二重 NAT を意味するわけではありません。2台目が純粋な AP モードなら、通常はこの通信に NAT がもう1段加わりません。より複雑なネットワークでは、アドレス変換を伴わない純粋なルーティングを使う場合もあります。

また、DHCP、ルーティング、NAT、ファイアウォールは別々の機能です。家庭用機器ではこれらがまとめて有効・無効にされることが多いため、同じものだと誤解されがちです。**DHCP だけを無効にしても、NAT がなくなった証拠にはなりません。**

## 二、動画は普通に見られるのに、外から NAS にアクセスできないのはなぜか？

一般的なステートフル IPv4 NAT では、機器が外部サービスへ能動的にアクセスすると、変換の記録が作られます。応答はその記録に沿って戻るため、要求元の内部機器に届きます。

外部のクライアントが新しい接続を能動的に開始する場合は別です。クライアントに分かるのは家庭の出口アドレスとポートだけで、家のどの NAS が宛先なのかは自動的には分かりません。

先ほどの二重構成を例に、ONU のインターネット側で利用可能な独立したパブリック IPv4 アドレスがあり、外部からの TCP 接続を、NAS 上で設定済みの HTTPS サービスへ最終的に届けたいとします。論理上の転送経路は、たとえば次のようになります。

```text
外部クライアント → 家庭のパブリック IPv4 の TCP 54443
ONU のルール     → 192.168.1.2 の TCP 54443
Mesh のルール    → 192.168.50.10 の TCP 443
NAS             → 対応するアドレスとポートでサービスが実際に待ち受け、その接続を許可
```

これは転送関係を説明するための例にすぎません。NAS の管理画面を直接公開することを勧めるものではなく、実際のネットワークで動作確認したものでもありません。

Mesh に最後の転送ルールだけを設定した場合、外からの要求はそもそも Mesh に到達しない可能性があります。内側のルールがどれほど正しくても、届いていないデータを受け取ることはできません。

2段階のマッピングがどちらも正しくても、プロトコルが一致しているか、NAS のアドレスが変わっていないか、サービスがループバックアドレスでしか待ち受けていないのではないか、ホストのファイアウォールが許可しているか、戻りの経路は正しいかも確認が必要です。TCP の転送では、サービスが必要とする UDP の転送を代用できません。

二重 NAT が速度測定で表面化するとは限らない理由も、ここにあります。Google の公式説明によると、多くのユーザーには目立ったネットワーク性能の差は生じませんが、ゲーム、ポート転送、UPnP などの利用には影響する可能性があります。[1] したがって、NAT が2段あるというだけで、あらゆる遅さの原因だと断定することはできません。ブリッジ化すれば速度測定の結果が必ず上がる、と約束することもできません。

問題が「写真をアップロードするとビデオ通話が途切れる」なら、前の記事に沿って、回線が混雑したときの遅延も確認する必要があります。一方、「家ではアクセスできるが、外ではまったくつながらない」なら、まず接続経路と入口の条件を確認すべきです。

## 三、最も重要な区別：2つ目の関門は家の中か、それとも通信事業者側か？

ブリッジ化の解説で特に見落とされやすいのが、この層です。

通信事業者は、キャリアグレード NAT、つまり CGN を使い、複数の契約者に1つのパブリック IPv4 アドレスを共有させてインターネットへ接続している場合があります。この場合、家庭内の二重 NAT を1段に減らしても、外側には通信事業者が管理するアドレス変換が残ります。[2]

**ONU のブリッジ化で変えられるのは家庭内の役割分担であり、通信事業者から独立したパブリック IPv4 アドレスが自動的に割り当てられるわけではありません。**

判断する際は、実際に通信事業者へ接続しているインターネットインターフェースを確認します。ONU がルーティングを担っているなら、下流の Mesh の WAN アドレスを見るだけでは不十分です。そこに 192.168.1.2 が割り当てられていることからまず分かるのは、Mesh が ONU の内部ネットワークにつながっているということです。

次の情報を並べて比較します。

| 記録する情報 | 確認する場所 | 主な目的 |
|---|---|---|
| NAS のアドレス、サブネットマスク、デフォルトゲートウェイ | NAS のネットワーク設定 | NAS がどのサブネットに属し、外部宛ての通信をどこへ送るか確認する |
| 自分で購入したルーターの WAN、LAN、動作モード | ルーターのステータス画面 | 2つ目の内部ネットワークを作っているか、NAT を行っているか確認する |
| ONU のインターネット接続の WAN IPv4 と動作モード | ONU のステータス画面、または通信事業者への確認 | 家庭の外側にも調査すべきアドレス変換があるか見極める |
| 同じ時点で外部サービスから見える出口の IPv4 | 家庭内ネットワークから IPv4 確認サービスにアクセス | インターネットインターフェースのアドレスと照合する |

比較する前に、同じプロトコルファミリー、同じ出口経路を見ていることに注意してください。ブラウザーがプロキシを使っている、機器で VPN が有効になっている、ネットワークに複数の WAN がある、といった状況は判断を妨げます。ある画面が IPv6 を表示し、別の画面が IPv4 を表示しているなら、直接比較はできません。

よく使われるアドレス範囲は次のとおりです。

| IPv4 の範囲 | 意味 | 推測できること |
|---|---|---|
| 10.0.0.0～10.255.255.255 | RFC 1918 のプライベートアドレス | そのアドレス自体はグローバルにルーティング可能なパブリックアドレスではない |
| 172.16.0.0～172.31.255.255 | RFC 1918 のプライベートアドレス | 172 で始まるアドレスがすべてプライベートアドレスというわけではない |
| 192.168.0.0～192.168.255.255 | RFC 1918 のプライベートアドレス | 家庭内などの内部ネットワークでよく使われる |
| 100.64.0.0～100.127.255.255 | RFC 6598 の共有アドレス空間 | CGN でよく使われる。RFC 1918 のプライベートアドレスとは別の分類 |

最初の3つの範囲は RFC 1918、共有アドレスの範囲は RFC 6598 の 100.64.0.0/10 に基づきます。[2][3]

これは IPv4 の特殊用途アドレスを網羅した表ではありません。表に載っていないからといって、インターネットからの着信を受けられると証明されたわけではありません。

実際のインターネットインターフェースに共有アドレスが割り当てられ、外部からは別の IPv4 が見えているなら、通信事業者側の NAT が重点的な調査対象です。ただし、パソコンの仮想ネットワークアダプターのどれかに 100.x のアドレスがあるというだけで、回線に CGN が使われていると断定してはいけません。まず、どのインターフェースを見ているのか確認する必要があります。

逆に、WAN アドレスと外部に表示されるアドレスが一致していても、それは条件の1つを裏づけるだけです。通信事業者によるフィルタリング、機器のファイアウォール、ポートのルール、サービスの待ち受け状態によって、接続が阻まれる可能性は残ります。RFC 6598 も、アドレスがグローバルに一意に見えても、必ずしもグローバルに到達可能だと証明できるわけではないと注意を促しています。[2]

## 四、2つの変更方法：どちらをメインルーターにするか？

構成を把握してから、初めて動作モードを選ぶ価値があります。

**方法 A：ONU がルーティングを担い、追加した Mesh またはルーターを AP にする。**

既存の出口が安定して動いており、改善したいのが電波の届く範囲だけという家庭に向いています。通常の端末は上流ネットワークからアドレスの割り当てを受け、追加機器は無線接続を担います。意図せず2つ目の内部ネットワークを作ることを避けられます。

ただし、購入した機器を AP モードにすると、それまでのポート転送、ペアレンタルコントロールなど、ルーティング経路に依存する機能が使えなくなる場合があります。それらの役割は上流の機器や別のシステムが担う必要があり、モード変更後もすべての機能が従来どおり有効だと思ってはいけません。

**方法 B：ONU のインターネット接続をブリッジ化し、自分で購入したルーターに出口を担わせる。**

自分で購入したルーターで、ファイアウォール、アドレス割り当て、VPN、SQM を管理したい家庭に向いています。PPPoE 接続が必要か、サービス用 VLAN をどう扱うか、IPv6 のプレフィックス委譲に対応するかは、通信事業者の実際の接続方式によって決まります。

ここでいう変更は、対象となるインターネット接続を確認して調整することであり、ONU の全設定を一括で消去することではありません。IPTV、電話、通信事業者による管理には、それぞれ別のサービス構成があるかもしれません。変更前に接続情報、互換性のある設定方法、復旧方法を確認し、短時間の接続断を許容できる時間帯に作業してください。

| 判断条件 | 先に検討する価値が高い方向 | 必ず確認すべき代償 |
|---|---|---|
| カバー範囲だけを広げたい。上流のルーター機能で足りる | 追加機器の AP モード | Mesh やゲストネットワークの分離などが AP モードでも維持されるか |
| 自分で購入したルーターの出口機能を一元的に使いたい | ONU のインターネット接続をブリッジ化 | 接続方式、ルーターの性能、IPv6、付加サービス |
| ONU を変更できず、当面は既存ネットワークも触りたくない | 二重構成を維持し、必要に応じて設定 | 着信のマッピングと障害調査で2段階を管理する必要があり、外側の CGN は別途対処が必要 |
| インターネット側が自分では設定できない共有 IPv4 | 通信事業者に確認するか、IPv6、メッシュ VPN／中継を検討 | 家庭内のブリッジ化では、外部から到達できる条件の代わりにならない |

もう1つ、購入時に特に間違えやすい点があります。**AP、ブリッジ、Mesh を組み合わせたときの機能は製品ごとに異なります。**

TP-Link の Deco の公式文書では、AP モードで既存ネットワークに接続でき、独自のサブネットを作らず、イーサネットバックホールにも対応すると説明されています。一方で、ゲートウェイ機能の一部は使えなくなります。[4] Google Nest Wifi の公式説明では、メイン機器のブリッジモードは単一機器の構成にのみ適用され、その構成で複数機器の Mesh を作ることはできないとされています。[5]

この2つの説明は矛盾しません。異なる製品の実装について述べているからです。購入時や設定変更時には、具体的な型番、ハードウェア版、ファームウェア、地域向けの文書を確認し、ブランド A での経験をブランド B にそのまま当てはめないでください。

## 五、DMZ、UPnP、DDNS では解決しないことが多いのはなぜか？

それぞれ用途はありますが、「すべてのネットワーク境界をなくす」スイッチではありません。

家庭用ルーターの画面にある「DMZ ホスト」は通常、ほかのルールで処理されなかった着信トラフィックの一部を、指定した内部機器へ渡す機能です。具体的な動作は実装によって異なります。一般には元の NAT 構成の中にとどまるものであり、企業ネットワークで独立した安全領域として設計する DMZ とは別物です。

ONU の DMZ の宛先を下流ルーターにすると、外側の転送を簡略化できる場合はあります。しかし、それによって二重 NAT がなくなるわけでも、管理できない通信事業者側の CGN を越えられるわけでもありません。下流のルーターには、引き続き明確なファイアウォール設定とサービスの入口が必要です。

UPnP のような自動ポートマッピングの仕組みでは、アプリケーションからゲートウェイにマッピングの作成を要求できます。ただし、内側のゲートウェイで「成功」と表示されても、それだけで外側のマッピングも完了したとは証明できません。製品によっては追加の処理機構を備える場合もありますが、経路全体を確認する必要があります。

DDNS は名前が指すアドレスを更新するものです。解決するのは「アドレスが変わった後、入口をどう見つけるか」であり、NAT のマッピングを作ったり、ファイアウォールに通信を許可させたりはしません。ドメイン名が共有出口アドレスに名前解決されることと、外部からの要求が自分の NAS に正確に届くことは、別の話です。

したがって、「ドメイン名が正しく名前解決される」「UPnP が成功と表示される」「DMZ を有効にした」のどれか1つを、リモートアクセスの条件が整った証拠として扱わないでください。

## 六、独立したパブリック IPv4 がなくても、別の経路を使えるか？

検討できます。ただし先に、「自分だけが使う」のか「誰でも使えるようにする」のかを区別する必要があります。

外出先から自分で NAS や Home Assistant にアクセスするだけなら、認証を伴うメッシュ VPN などの接続が要件に合うことが多く、管理画面を公開入口にする必要はありません。一方、誰でも開けるウェブサイトを提供するなら、ドメイン名、入口となるサービス、証明書、公開アクセスのポリシーも考慮しなければならず、個人用の接続方法をそのまま流用することはできません。

**1つ目の経路は IPv6 です。**

適切なグローバルユニキャストアドレスとルーティング条件があれば、IPv6 では従来の IPv4 NAT 経路を通らずに済みます。ただし、IPv6 を有効にするだけでリモートアクセスできるわけではありません。クライアント側のネットワークから宛先へ到達でき、サービスが対応するアドレスで待ち受け、ゲートウェイとホストのファイアウォールが必要な接続を許可している必要があります。アドレスやプレフィックスが変わった後も、名前とルールが有効でなければなりません。

RFC 6092 が扱う住宅向け IPv6 のセキュリティ機能には、ステートフルフィルタリングと、ポリシーに基づく例外設定が含まれます。IPv4 NAT がないことは、境界でのフィルタリングがないことを意味しません。[6] 目標は、確認したサービスの経路だけを開くことであり、IPv6 のファイアウォールをすべて無効にすることではありません。

**2つ目の経路は、NAT 越えと中継に対応したメッシュ VPN などの接続ツールです。**

Tailscale の公式文書を例にすると、接続には直接接続、DERP 中継、peer relay があり、直接接続に失敗した場合は中継経路を使用できます。[7] これにより利用者が着信の入口を設定する負担は軽くなりますが、どのネットワークでも必ず成功するとは限りません。また、「接続済み」を「必ず直接接続している」と解釈してはいけません。

Tailscale をすでにインストールして設定した機器では、まず対象への通信を一度発生させてから、次を確認できます。

```sh
tailscale status
tailscale ping NASのデバイス名
```

2行目のデバイス名は、実際の名前に置き換える必要があります。文書によると、`direct`、`relay`、`peer-relay` などの状態から経路を判断できます。また、当初は中継を経由した接続が、その後直接接続に切り替わる場合もあります。[7] これらは読者が実行できる確認コマンドであり、この記事であなたの家庭の接続環境に対して実行したものではありません。

大きなファイルにアクセスする場合は、中継の場所、利用可能な帯域、サービスのポリシーも確認する価値があります。外出先から NAS のトップページを開けたことは、ほんの一部を確認したにすぎません。ファイル転送、接続の安定性、その経路が自分の費用や管理の想定に合うかも試す必要があります。

## 七、この順序で調べると、再起動を繰り返すより原因を見つけやすい

**第1段階：まずサービスがローカルで正常に動くことを確かめる。**

NAS と同じサブネットにある機器から、実際のサービスアドレスにアクセスします。ローカルでも開けないなら、公開側の入口を変更する前に、サービス、待ち受け、認証、ホストのファイアウォールを確認してください。

**第2段階：家庭内の経路を最後まで描く。**

前述の4項目を記録し、ONU と自分で購入したルーターがそれぞれどのモードか確認します。IPv4、IPv6、プロキシ、メッシュ VPN などの接続ツールが異なる経路を使っていないか見極めます。Wi-Fi の名前でサブネットを判断してはいけません。同じ SSID でも同じサブネットとは限らず、SSID が違っても別のサブネットとは限りません。

**第3段階：家庭の外側から着信できる条件を確認する。**

インターネットインターフェースには共有アドレスやプライベートアドレスが割り当てられているでしょうか。外部から見える IPv4 は異なるでしょうか。通信事業者は利用可能な着信方法を提供しているでしょうか。この層がはっきりしないうちに家庭内の転送ルールを繰り返し調整しても、得られるものは通常わずかです。

**第4段階：一度に1つの明確な経路だけを検証する。**

IPv4 のポート転送を試すなら、プロトコル、外部ポート、対象サービスを固定します。IPv6 を試すなら、実際の接続が IPv6 を使っていることを確認します。メッシュ VPN などの接続を試すなら、直接接続か中継かを記録します。3種類の入口を同時に有効にして、たまたま成功した1回を最後に押したボタンの効果だと判断してはいけません。

テストは、実際に外部のネットワークから行う必要があります。たとえばスマートフォンの Wi-Fi をオフにしてモバイル回線を使い、その際も VPN 経由で自宅に戻っていないか注意します。家の中からパブリックなドメイン名にアクセスするだけでは、NAT ループバックや内部 DNS が関わる可能性があり、外部からのテストの代わりにはなりません。

**第5段階：ログを使って障害の位置を絞る。**

機器が対応していれば、対象インターフェース、転送ルールのカウンター、ログを確認し、要求がどこまで到達したかを調べます。入口の機器には記録があるのに NAS が受け取っていなければ、内部の転送経路をさらに確認します。NAS が受け取っているのにアプリケーションが失敗するなら、戻りの経路、プロトコル、サービス設定を調べます。ログがないことはトラフィックがないことを意味せず、該当する記録機能が有効になっていないだけかもしれません。

**第6段階：変更後も継続して使えるか検証する。**

```text

実際の経路：IPv4 転送 / IPv6 / メッシュ VPN 直接接続 / 中継
ONU とメインルーターの動作モード：
対象アドレス、プロトコル、ポート：
ローカルからのアクセス結果、外部からのアクセス結果：
ルールのカウンターまたはログの手がかり：
再起動後に復旧するか、アドレス変更後に復旧するか：
失敗時にどの設定へ戻すか：
```

再起動や回線の再接続によって、動的アドレス、自動マッピング、DNS 更新のタイミングが変わる場合があります。一度アクセスに成功した後も、ルールが永続的に保存されているか、重要な機器のアドレスが安定しているか、接続の復旧に手作業が必要かを確認してください。検証のために、家族がネットワークを使っている最中に不用意に回線を切断してはいけません。

## 八、管理しやすい家庭内ネットワークには、明確な役割分担がある

目的が5階建ての家全体をカバーすることだけなら、各階のルーターに意図せず独立した内部ネットワークを作らせる必要はありません。出口を担うメインルーターを明確に決め、ほかの機器は必要な機能に応じて AP、スイッチ、管理された無線ノードとして配置できます。

来客用端末、カメラ、仕事用機器を分離する必要があるなら、サブネット、アクセスルール、サービス検出を明確に設計すべきです。複数のネットワークを維持すること自体は間違いではありません。問題なのは、偶然できたネットワーク境界を「機器を1台増やせば安定する」と捉えることです。

リモートアクセスについても、まず次の1文を明確にしてください。**誰が、どこから、どの経路を通って、家のどのサービスにアクセスする必要があるのか？**

この問いに答えられれば、NAT を1段減らすべきか、ファイアウォールのルールを調整すべきか、通信事業者にサービスを確認すべきか、それとも代償を理解したうえで中継経路を使うべきかが分かります。

ルーターを1台買い足せば、カバー範囲は広げられます。それぞれの機器の役割を明確にしてこそ、次の障害で原因を見つけやすくなります。
